# Contribution Guidelines

Thanks for wanting to add something. This list is a curation, not a collection, so entries are
judged on whether a reader can act on them.

## Adding an entry

Open a pull request that adds one entry, at the bottom of the most appropriate category:

```markdown
- [Name](https://github.com/owner/repo#readme) - What it does, stated objectively, ending in a period.
```

Before you open it, check that:

1. The project is open source, with the source publicly available.
2. It is relevant to deciding whether agent or model work is actually done. Measurement,
   inspection or enforcement all count. A general-purpose agent framework does not.
3. It is maintained: a commit or release within the last year, or it is foundational enough that
   people still build on it.
4. It is not archived or deprecated.
5. It is not already on the list.
6. The description says what the project is, not what it is good for. `Mobile operating system for
   Apple phones and tablets.` not `Resources and tools for iOS development.`
7. The URL ends in `#readme` so the link lands on the documentation rather than the file tree.

## Removing an entry

Open an issue or a pull request if something on the list has been archived, abandoned, or
superseded by a better project. Say which and why.

## What does not belong

- Anything closed source.
- Marketing copy, taglines, or a description that would not help a reader decide whether to look.
- Projects that only claim to verify without a way to see the check.
- Your own project, submitted without saying you are its author. Being the author is fine. Saying
  so is required.
